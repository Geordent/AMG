# AMG — концепция краудсорсинга: «полезно, легко, весело, без мусора» (2026-10-27)

Статус: предложение, решений пока нет. Код и данные не менялись.

## Задача

Дать туристам и местным подтверждать и поправлять объекты на карте (на месте ли, точно ли стоит точка), а также делиться маршрутами. Ограничения автора:

- без базы данных и тяжёлого бэкенда;
- элегантно, легко, полезно, весело;
- не соцсеть: без профилей, ленты, лайков и комментариев;
- защита от спама, троллей и злопыхателей.

## Что уже есть в коде

| Заготовка | Где | Состояние |
|---|---|---|
| «Я здесь»: проверка, что человек рядом с объектом; допуск зависит от точности GPS; ручной выбор при плохом сигнале | `iAmHere`, `PRECISION_TOL_M`, `armManualPick` | работает, выключено флагом `AMG_UGC_ENABLED = false` |
| Deep-link в Telegram-бота с компактным payload: `c` = подтвердить, `k` = поправить, id объекта и координаты | `makeHerePayload`, `AMG_BOT_USERNAME` | готово, бота нет онлайн |
| Чтение фида подтверждений и значок «✓ проверено» | `loadContributions`, `data/contributions.json`, `verifiedBadge` | готово, фид пустой |
| Черновик бота и правил | `amg-contrib-bot.mjs`, `contrib-lib.mjs` | **только на сервере zimablade, не в репозитории** |

Вывод: половина пути пройдена. Не хватает лёгкого «приёмника» ответов и правил, которые превращают ответы в данные.

## Пять принципов

1. **Вопросы, а не текст.** Пользователь не пишет — он выбирает ответ. Нет поля для текста — некуда писать спам, оскорбления и бред.
2. **Нужно быть на месте.** Вопросы о месте задаются только тому, кто рядом (уже работает «Я здесь»). С дивана карту не испортить.
3. **Согласие, а не доверие.** Один ответ — это сигнал. Изменение происходит, когда согласны несколько независимых людей.
4. **Хранитель и git на последнем шаге.** Значки «проверено» выставляются автоматически. Изменение данных (сдвиг точки, статус «закрашен») приходит как Pull Request, его принимает автор проекта. Всё видно в истории, любое решение откатывается.
5. **Радость — личная, не публичная.** Никаких рейтингов людей и ленты. Весело становится от коллекции штампов, «спасибо» от руки и ощущения «я помог».

## Что можно спрашивать (квесты)

| Вопрос | Ответы | Условие | Что меняет |
|---|---|---|---|
| Объект ещё на месте? | Да / Повреждён / Закрашен или заменён / Не нашёл | рядом с объектом | значок «проверено <месяц>» или пометка «нужна проверка» → статус |
| Точка стоит точно? | Да / Сдвинуть (перетащить булавку, не дальше 150 м) | рядом | Pull Request с новыми координатами |
| Видно с улицы? | Да / Только со двора / Закрыто | рядом | поле доступа `access` / видимость |
| Фото (позже) | снимок через бота + согласие на лицензию CC BY-SA | рядом | ручная модерация, затем `media` |

Названия, художники, тексты — **не краудсорсим** через быстрые вопросы. Для таких правок остаётся кнопка «Обратная связь» → GitHub Issue: людей с такими правками мало, и обычно они знают тему.

## Как это устроено без базы данных

```
Сайт («Я здесь» → вопрос → ответ)
   │  deep-link t.me/<бот>?start=<payload>  (уже в коде)
   ▼
Telegram-бот = Cloudflare Worker (без сервера, бесплатный тариф)
   │  проверяет: формат, допуск GPS, лимиты; хеширует Telegram ID с солью
   ▼
Файл-«входящие» в репозитории: ветка contrib, contrib/inbox/2026-10.jsonl
   │  (ответ = одна строка; через GitHub API, без БД)
   ▼
GitHub Action по расписанию (раз в сутки): правила согласия
   ├─► data/contributions.json — значки «проверено», «нужна проверка» (автоматически, деплой)
   └─► Pull Request с правками координат и статусов → автор принимает → деплой
```

Почему Telegram: аккаунт уже есть у аудитории; бот сразу даёт стабильный ID без собственной регистрации; у Telegram есть своя защита от ботов; deep-link уже встроен в сайт. Альтернатива без Telegram — форма на сайте + Cloudflare Worker + капча Turnstile. Она проще для пользователя, но слабее против спама. Её можно добавить позже как второй вход.

Цена: Cloudflare Workers — бесплатный тариф (100 тыс. запросов в сутки); GitHub Actions бесплатны для публичного репозитория. Базы данных нет, сервера нет.

## Защита от мусора и злопыхателей (слои)

1. **Закрытые ответы** — нет текста, нет ссылок, нет картинок без модерации.
2. **Проверка присутствия** — расстояние до объекта ≤ допуска по точности GPS; точность хуже 100 м отклоняется; «телепорт» (два ответа в разных концах города за минуту) отклоняется.
3. **Лимиты** — один человек: не больше 20 ответов в сутки; один ответ на объект раз в 30 дней.
4. **Порог согласия** — значок «проверено» — от 2 человек; статус «закрашен/пропал» — от 3 человек в разные дни; сдвиг точки — от 3 предложений, лежащих в пределах 25 м друг от друга (берётся медиана).
5. **Скрытая надёжность** — новые аккаунты весят меньше; тот, чьи ответы обычно совпадают с итогом, весит больше. Публично это нигде не видно.
6. **Тихое игнорирование** — подозрительные ответы принимаются (человек видит «спасибо»), но не учитываются. Троллю не на что реагировать.
7. **Хранитель** — всё, что меняет данные, приходит Pull Request'ом. Ничего не удаляется с карты автоматически: худшее, что может сделать толпа, — пометка «нужна проверка».
8. **Откат** — любое решение — коммит, `git revert` возвращает всё назад.

## Чтобы было весело и дружелюбно (и не соцсеть)

- **Паспорт путешественника.** Каждый «Я здесь» ставит штамп в личный блокнот (в стиле «Скетчбука»). Хранится в браузере, без аккаунта. Коллекции: «Мозаики Сабуртало 7/12», «Все бани Абанотубани». Мотивирует ходить, а не спорить.
- **«Спасибо» от руки** сразу после ответа; если ответ стал решающим — «Ты третий — точка подтверждена ✓».
- **Бот возвращается с хорошими новостями**, а не с рассылкой: «Твой ответ помог — мурал на Атонели отмечен как сохранившийся».
- **История доверия в карточке**: «подтверждено 3 людьми · октябрь 2026». Без имён.
- **Ежемесячная сводка** в канале или на сайте: «В октябре 42 проверки, поправлено 5 точек». Чувство общего дела без ленты.

## Маршруты пользователей — без соцсети

- **Маршрут = ссылка.** Пользователь собирает «Мой день» у себя (в браузере) и делится ссылкой вида `…/AMG/#route=site-0003,site-0101,site-0042`. Ничего не хранится на сервере, друзья открывают ссылку и видят маршрут.
- **Подборка от путешественников.** В боте есть кнопка «Предложить маршрут». Хорошие маршруты автор добавляет в `data/routes.json` (по желанию — с подписью-ником). Без лайков и комментариев: подборка курируется, а не ранжируется толпой.

## Обновление 2026-10-27: решения автора, этап 0 сделан

**Решения:** GO на этап 0; канал ответов — Telegram. Хостинг бота пересмотрен (ниже).

### Этап 0 — реализовано (index.html, без бэкенда)

| Что | Как работает |
|---|---|
| Паспорт путешественника | «Я здесь» (флаг `AMG_STAMPS_ENABLED`) проверяет GPS у объекта и ставит штамп в `localStorage['amg-passport']`; панель «Паспорт»: штампы с датой от руки, коллекции по категориям («Муралы 1/258»), тап по штампу → объект. Далеко от объекта штамп не ставится |
| «Мой день» | «+ В мой день» в карточке, попапе и «Подробно»; панель со списком, ↑ ↓ ×, расстояние и время между точками (по прямой), пунктир «карандашом» на карте; до 25 точек; `localStorage['amg-day']` |
| Маршрут-ссылка | «Поделиться ссылкой» → `…/AMG/#route=site-0450,site-0003,…`; у друга открывается «Маршрут по ссылке» с кнопкой «Сохранить как мой день»; неизвестные id отбрасываются; без сохранения чужой маршрут не остаётся на карте |
| Сообщить о проблеме | 6 готовых вариантов → форма GitHub Issue `.github/ISSUE_TEMPLATE/object-report.yml`, поля заполняет сайт (`site`, `problem`, `position`); если «Я здесь» показал, что метка неточна, повторное нажатие открывает эту форму с координатами пользователя |
| Приватность | `privacy.html` (ru/en/ka): паспорт и день только в браузере; координаты уходят на GitHub, только если человек сам отправит форму |

Проверено сценарным тестом в Edge: 12/12 проверок (штамп рядом / нет штампа далеко, порядок дня, пунктир, ссылка у «друга» на телефоне, сохранение, ссылка формы GitHub), ошибок страницы нет; общий smoke (каталог, язык, офлайн) — ok.

Для автоприсвоения метки форме нужна метка `report` в репозитории (создаётся один раз: `gh label create report`).

### Хостинг бота (этап 1) с учётом РФ — пересмотрено

Факты на октябрь 2026:
- Telegram в РФ заблокирован (полная блокировка с апреля 2026, работает только через VPN). Для ответов на месте в Грузии это не мешает — Telegram там работает; администрировать бота автору — через VPN.
- Cloudflare: с июня 2025 российские провайдеры режут доступ к сайтам за Cloudflare (лимит ~16 КБ на запрос). Сведений об отключении аккаунтов из РФ не найдено. Для бота это не критично (webhook вызывает Telegram, а не пользователь), но это лишняя точка риска и ещё один аккаунт.
- Deno Deploy объявил (2026-10-09) о переходе в Cloudflare и закрытии через ~6 месяцев — не подходит. Netlify перешёл на кредиты (кончились — сайт на паузе). Vercel Hobby — только некоммерческое использование.

**Рекомендация:** бот без отдельного хостинга — **GitHub Actions по расписанию**. Workflow раз в 5–10 минут забирает новые сообщения через Telegram `getUpdates`, проверяет их, отвечает и дописывает строки в `contrib/inbox/*.jsonl`; ночной workflow считает согласие. Нужен только токен бота в секретах репозитория. Плюсы: нет новых аккаунтов и серверов, всё в одном месте и в истории git, бесплатно для публичного репозитория. Минус: ответ бота приходит с задержкой в несколько минут (сайт благодарит сразу). Если позже понадобятся мгновенные ответы — тот же код переносится на webhook (Cloudflare Worker или другой хост) без изменения формата данных.
