## 1. Краткое резюме

**Что уже готово**

- Модель готовых маршрутов: `data/routes.json` — `id`, локализованные `title`/`theme`/`desc`, массив `stops` из ID мест.
- Связь с каталогом через канонический `site-NNNN`: маршрут не хранит названия/координаты, а разрешает их через `catalog.siteById` из `data/sites.geojson` (`index.html:1026-1042`, `3678-3683`).
- Валидация маршрутов: `scripts/validate-routes.mjs` (ID, переводы, ≥2 точек, дубли, существование места, статус `active`, соседние точки ≤1500 м); запускается локально и в CI (`.github/workflows/pages.yml:27-31`).
- Панель «Мой день»/«Маршруты»: список остановок, расстояния/время, ↑ ↓ ×, итог, имя, шаринг ссылкой, импорт `#route=`/`#ready=`, сохранение готового маршрута как личного (`index.html:3590-3794`).
- Линия на карте: GeoJSON `amg-day` + слой `amg-day-line`, пунктир, вписывание в экран и анимация прорисовки (`index.html:3612-3630`, `3699-3727`).
- Локализация ru/en/ka: тексты интерфейса в `LB`, поля маршрута — объекты `{ru,en,ka}`, выбор через `pick()` (`index.html:693-701`, `805-840`).
- Адаптивность: мобильная нижняя панель / десктопная левая панель, увеличенные контролы на coarse pointer (`index.html:77-82`, `99-127`).
- Офлайн/кэш: `data/*.json` и `*.geojson` — network-first с fallback в кэш (`sw.js:14-22`); `routes.json` загружается по требованию.
- Публикация: `data/` целиком копируется в `site/`, маршруты доступны как статический JSON (`.github/workflows/pages.yml:105`).

**Чего объективно не хватает (подтверждено кодом/данными)**

- Полей тематизации: нет машиночитаемой категории/тегов, длительности, транспорта, сезонности, сложности, источников, геометрии, заметок к остановкам, фото маршрута.
- Готовый маршрут не может включить место без активной арт-работы: валидатор требует `status === 'active'` для каждой остановки (`scripts/validate-routes.mjs:27`), хотя в `sites.geojson` уже есть 41 «place-centric» место без работ (бани, наследие, природа) и они отображаются на карте.
- «Впечатления» (`data/experiences.geojson`, 60 объектов) не имеют стабильных ID и не могут быть остановками маршрута: маршруты разрешаются только через `sites.geojson`.
- Нет отдельной геометрии маршрута: только прямые отрезки между остановками; нет GPX/трека, реальной прокладки по дорогам, высот, сложности.
- Нет одновременного отображения нескольких маршрутов и нет отдельного слоя/подсветки остановок.
- Нет отдельного каталога маршрутов с фильтрами/поиском: готовые маршруты — плоский список внутри панели «Мой день»; `theme` — свободный текст, не ключ категории.
- Нет per-route SEO: ссылки — hash-фрагменты, `<title>`/OG/description статичны, `sitemap.xml` содержит только 3 URL.
- Нет автоматической проверки маршрутов в PR: `pages.yml` реагирует на `push` в `main` и `workflow_dispatch`, но не на `pull_request` (`.github/workflows/pages.yml:2-5`).
- Личный маршрут не устойчив к удалению места: `renderDay()`/`copyDayList()` не фильтруют отсутствующие в каталоге ID (риск падения панели).
- `openReadyRoute()` не применяет лимит 25 точек, хотя личный маршрут и `#route=` применяют (`index.html:3692` vs `3535`, `3606`, `3760`).
- Нет фотографий в интерфейсе маршрута, хотя `media[]` есть у 45 мест (включая 35 из 41 place-centric).

## 2. Текущая схема данных

### 2.1 `data/routes.json`: поля и связи

Фактическая структура (`data/routes.json:1-34`):

```json
{
  "version": 1,
  "note": "Готовые маршруты по районам. stops — id мест в порядке обхода...",
  "routes": [
    {
      "id": "sololaki-old-town",
      "title": { "ru": "…", "en": "…", "ka": "…" },
      "theme": { "ru": "…", "en": "…", "ka": "…" },
      "desc":  { "ru": "…", "en": "…", "ka": "…" },
      "stops": ["site-0022", "site-0533", "..."]
    }
  ]
}
```

| Поле | Тип | Обязательность по коду | Кто использует | Комментарий |
|---|---|---|---|---|
| `version` | number | нет | никто | Информационное; `scripts/validate-routes.mjs` его не читает. |
| `note` | string | нет | никто | Информационное; в UI не выводится. |
| `routes` | array | фактически да | клиент и валидатор | Если нет/не массив — клиент показывает пустой список (`index.html:3679-3681`). |
| `routes[].id` | string `^[a-z0-9-]+$` | да | `#ready=`, `openReadyRoute` | Уникален среди маршрутов (`validate-routes.mjs:19-20`). |
| `routes[].title` | `{ru,en,ka}` | да | заголовок панели, шаринг | Валидатор требует непустые все три языка (`:21`); клиент дополнительно делает fallback через `pick()`. |
| `routes[].theme` | `{ru,en,ka}` | да | подпись в списке готовых | Свободный текст, **не** ключ категории/фильтра. |
| `routes[].desc` | `{ru,en,ka}` | да | описание в панели | Короткий абзац; длины/структуры валидатор не проверяет. |
| `routes[].stops` | array of site ID | да | линия, список, расчёты | ≥2, без дублей внутри маршрута; порядок = порядок обхода. |
| любые доп. поля | — | нет | никто | Клиент сохраняет их через `{ ...r }` (`index.html:3680`), но не отображает; валидатор игнорирует. |

Обязательные/необязательные поля в терминах фактического кода: **обязательны** `id`, `title`, `theme`, `desc`, `stops` (иначе валидатор падает); `version` и `note` — необязательные метаданные, не влияющие на поведение.

**Примеры из текущих данных**

1. `sololaki-old-town` — «Старый город: от площади Свободы по Сололаки» (`data/routes.json:6-10`), тема «Муралы и стрит-арт», 15 остановок, первая `site-0022`, последняя `site-0508`, 2,81 км по прямой.
2. `vake-murals` — «Ваке: муралы на Чавчавадзе и Чиковани» (`:13-17`), 8 остановок, `site-0420 → site-0426`, 3,07 км.
3. `varketili-open-air` — «Варкетили: музей под открытым небом» (`:27-31`), 17 остановок, `site-0465 → site-0471`, 4,22 км.

**ID, остановки, порядок**

- ID маршрута — человекочитаемый slug, только `[a-z0-9-]`, используется в `#ready=<id>`.
- `stops[]` — массив **канонических ID мест** (`site-NNNN`), не работ и не «впечатлений».
- Порядок массива — единственный источник порядка обхода. Алгоритма выбора/оптимизации нет; данные курируются вручную. Валидатор проверяет только, что соседние точки не дальше 1500 м (`validate-routes.mjs:28-31`), но не общую длину, не город/bbox, не самопересечения и не оптимальность.
- Маршрут не хранит координаты, названия, фото, адреса — всё берётся из места при отображении.

**Как маршрут связан с объектами каталога**

`stops[]` → `catalog.siteById` (`index.html:1026-1042`) → `data/sites.geojson`. Название — `siteTitle(f)` (`index.html:2971-2974`): сначала `properties.name`, затем название первой работы. Координаты — `geometry.coordinates` места. Карточка открывается по клику на строку через `focusSite(id)` (`index.html:3114-3118`). Фотографии маршрутом не используются; в карточке места они выводятся из `properties.media[]` (`mediaHtml`, `index.html:2017+`). Работы/художники/источники подтягиваются карточкой места, а не маршрутом.

**Что происходит при некорректных данных**

- Неизвестный `#ready=<id>`: `openReadyRoute()` делает `find` и молча выходит (`index.html:3690`).
- Неизвестный ID в `stops`: `validate-routes.mjs:26` даёт ошибку; клиент `loadRoutes()` вырезает такую точку (`index.html:3680`), и если остаётся <2 — маршрут исчезает; `#route=` дополнительно дедуплицирует и фильтрует ID (`:3759-3760`).
- Место без активной работы: валидатор падает (`validate-routes.mjs:27`, сообщение «не active (без работ)»); клиент статус не проверяет и показал бы такую точку, если бы данные дошли до сайта в обход CI.
- Отсутствующие координаты: `validate-data.mjs:200-211` требует `Point` с двумя конечными числами в окне Грузии; `validate-routes.mjs` сам геометрию не проверяет и при запуске отдельно может упасть на `geometry.coordinates`.
- Битый JSON/`stops` не массив: `getJson(...).then(...).catch(...)` в `loadRoutes()` (`index.html:3679-3681`) скрывает **весь** список готовых маршрутов, а не только плохой маршрут.
- Дубли остановок внутри маршрута: ошибка валидатора (`:23`); `openSharedRoute()` дедуплицирует, `openReadyRoute()` — нет (полагается на валидатор).
- Битый процент в `#route=` (например, `%`): `decodeURIComponent` в `openSharedRoute()` (`:3759`) не обёрнут в try/catch и может бросить исключение.
- Неизвестные/лишние поля маршрута: игнорируются; обратной совместимости не ломают.

**Проверки и где запускаются**

- `scripts/validate-routes.mjs`:
  - ID: формат `^[a-z0-9-]+$`, уникальность (`:19-20`);
  - `title`/`theme`/`desc`: все три языка непустые (`:21`);
  - `stops`: массив, ≥2, без дублей (`:22-23`);
  - каждая остановка существует в `sites.geojson` (`:26`);
  - статус остановки — `active` по **первой** работе сайта (`:12`, `:27`);
  - соседние остановки ≤1500 м (`:28-31`).
  - Не проверяет: максимум 25 точек, общую длину/bbox, наличие `geometry` (полагается на `validate-data`), дубли маршрутов по названию, размеры `desc`, доп. поля.
- `scripts/validate-data.mjs`:
  - канонические ID и уникальность (`:18-23`, `:149-151`);
  - `sites.geojson`: `Point`, конечные `[lng,lat]`, окно Грузии, `city` из `cities.json`, `name`/`address`/`precision`/`access`, `sources`, `media` (`:193-230`);
  - `artworks.json`: `site_id` формата `site-NNNN`, `site_id` существует в `sites.geojson` (`:239`, `:265`), статусы, источники, медиа (`:233-258`).
  - Не требует, чтобы у места была работа: 41 место без работ проходит `validate-data`.
- Локально: `README.txt:29`, `docs/RUNBOOK.md:25`.
- CI: `.github/workflows/pages.yml:27-31` — `validate-data`, `validate-experiences`, `contrib-test`, `extract-tiles`, `validate-routes` перед сборкой; затем `cp -r data site/` (`:105`).
- `pages.yml` не имеет триггера `pull_request` (`:2-5`), поэтому PR сам по себе не валидируется; проверка — локальный запуск или push в `main`.

### 2.2 Объекты и идентификаторы

- **Канонический ID** — `properties.id` в `data/sites.geojson`, формат `^site-\d{4,}$` (`scripts/validate-data.mjs:18-23`). Он используется:
  - в `artworks[].site_id` (`validate-data.mjs:239`, `:265`);
  - в `routes[].stops` (`validate-routes.mjs:26`);
  - в URL `#s=<siteId>` (`index.html:3122`, `3141-3144`);
  - в публичном фиде подтверждений (ключи `sites` в `data/contributions.json`).
- Глобальная уникальность ID проверяется через общий `allIds` (`validate-data.mjs:149-151`), поэтому `site-…`, `amg-…`, `artist-…`, `src-…` не пересекаются.
- Типы данных, существенные для маршрутов:
  - `sites.geojson` — 573 физических места. Два подвида: места с работами (532) и place-centric места без работ (41) с полями `topic` (`unusual`/`heritage`), `poi_kind`, `description`, `media`; на карте они уже получают категорию/семейство через fallback (`index.html:1160-1161`, `1184-1196`).
  - `artworks.json` — 539 работ, связь `site_id`; маршрут на работы не ссылается, но карточка места показывает их.
  - `experiences.geojson` — 60 «впечатлений» (бани, каньоны, канатки и т. п.); **стабильного `id` нет** ни в `properties`, ни на уровне feature (проверено всеми 60 объектами); отдельный слой (`index.html:1360+`); маршруты на него не ссылаются. Набор полей неоднородный, но у части объектов уже есть `hours`, `fee_*`, `media`, `website`, `phone`, `desc_*`, `addr_*` — содержательно это как раз тематический материал (бани, животные, природа), которому не хватает адресуемости.
  - `artists.json`, `sources.json`, `cities.json`, `transit.geojson` — вспомогательные; маршрут их напрямую не использует.
- **Можно ли добавить место, которого нет в каталоге арт-объектов?**
  - В `sites.geojson` — да, такие места уже есть (41, включая бани, монастыри, некрополи, канатные сети); карта их отображает.
  - В готовый маршрут — **сейчас нет**: `validate-routes.mjs:27` требует активную работу, а у этих 41 места работ нет. Клиентская часть (`loadRoutes`) статус не проверяет и такое место показала бы, но CI заблокирует.
  - «Впечатления» — нет: у них нет ID, и `loadRoutes`/`validate-routes` читают только `sites.geojson`.
- **Переиспользование в нескольких маршрутах** — модель поддерживает: `stops` хранит только ID, дублирования данных нет. В текущих 4 маршрутах пересечений нет (51 уникальная остановка = 15+8+11+17).
- **Переименование / удаление / смена ID**:
  - переименование места: маршрут не меняется, панель показывает новое `properties.name` через `siteTitle`; собственные `title`/`desc` маршрута не обновляются;
  - удаление места: `validate-routes` падает; клиент вырезает остановку, и маршрут остаётся, если ≥2 точек; `#route=`-ссылка молча теряет точку; `#ready=`-ссылка показывает усечённый маршрут или ничего, если осталось <2;
  - смена ID: для маршрута это удаление старого + добавление нового; одновременно ломаются `artworks.site_id` и старые ссылки `#s=`, `#ready=`, `#route=`;
  - личный «Мой день»: сохранённые в `localStorage` старые ID не мигрируют и не вычищаются; `renderDay()`/`copyDayList()` могут упасть на `siteTitle(undefined)` (`index.html:3636-3647`, `3743`), хотя `dayGeo()`/`fitDayMap()` такие ID отфильтровывают.

### 2.3 Существующая функция «Маршрут на день»

Подтверждено по коду (уточнения к уже известному описанию):

- Состояние (`index.html:675-682`):
  - `localStorage['amg-day']` — массив ID; при старте фильтруется только по типу `string`, не по наличию в каталоге;
  - `localStorage['amg-day-name']` — имя до 60 символов;
  - `stage0.dayShared` — временный импортированный/готовый маршрут (в памяти);
  - `stage0.dayRoute` — объект готового маршрута (в памяти);
  - `stage0.sharedName` — имя импортированного маршрута;
  - `stage0.routesP`/`stage0.routes` — кэш промиса и список готовых маршрутов.
- `dayList()` возвращает `stage0.dayShared || stage0.day` (`:3591`), то есть открытый готовый/чужой маршрут имеет приоритет над личным.
- Лимиты: `DAY_MAX = 25` (`:3535`), проверка в `toggleDay` (`:3606`) и в `openSharedRoute` (`:3760`); имя — 60 (`:3662`, `:3853`). `openReadyRoute` лимит **не** применяет (`:3692`), текущие готовые маршруты 8–17 точек.
- Импорт:
  - `#route=id,id,...&n=Имя` → `handleHash` (`:3136-3140`) → `openSharedRoute` (`:3757-3766`): decode, дедуп, фильтр по каталогу, срез до 25;
  - `#ready=<id>` → `handleHash` → `openReadyRoute` (`:3689-3694`): загрузка `routes.json`, поиск по ID, подстановка `stops`.
- Экспорт/обмен:
  - `dayShareUrl()` (`:3732-3737`): готовый маршрут → `#ready=<id>`; личный/импортированный → `#route=<ids>&n=<name>`;
  - `shareDay()` (`:3748-3756`) — `navigator.share` или буфер обмена;
  - `copyDayList()` (`:3738-3747`) — текст «название + нумерованный список + ссылка на карту»;
  - личный маршрут в URL автоматически не попадает — только при шаринге.
- Готовый → личный: `saveSharedRoute()` (`:3767-3776`) копирует `dayShared` в `stage0.day`, записывает `amg-day` и `amg-day-name`, очищает `dayShared`/`dayRoute`, делает `history.replaceState` без hash. Для готового маршрута в имя попадает его `title`; после сохранения ссылка становится `#route=…&n=…`, а не `#ready=…`.
- Конфликты личного и открытого готового:
  - пока открыт `dayShared`, панель и линия показывают его, а личный `stage0.day` скрыт;
  - кнопки «+ В мой день» в карточках продолжают менять именно `stage0.day`; изменения не видны, пока не закрыть/сохранить чужой маршрут;
  - `saveSharedRoute()` **заменяет** личный день целиком, без подтверждения;
  - `closeDay()` (`:3695-3698`) очищает чужой маршрут и возвращает личный;
  - список готовых маршрутов в панели скрыт, пока открыт чужой/готовый (`renderDay`, `:3651`);
  - счётчик на кнопке «Маршруты» считает личный `stage0.day`, а не открытый чужой (`stage0Labels`, `:3547-3551`).
- Переиспользуемое: `dayGeo`/`drawDay`, `fitDayMap`/`animateDayLine`, `renderDay`, `dayShareUrl`/`openSharedRoute`/`saveSharedRoute`, `loadRoutes`, `validate-routes` как шаблон проверки.

### 2.4 Отображение маршрутов на карте

**Подтверждено**

- Один GeoJSON source `amg-day` и один слой `amg-day-line` (`index.html:3624-3628`): цвет `#6E2639`, ширина 3.5, прозрачность 0.9, `line-dasharray [0.1, 2.2]`, `line-cap/join: round`. Слой вставляется под `sites-clusters`, если кластерный слой существует (`:3628`).
- Геометрия — `LineString` из координат остановок в порядке `dayList()` (`dayGeo`, `:3612-3616`); при одной точке линии нет.
- `drawDay()` обновляет `setData` или создаёт source/слой; при `style.load` вызывается снова (`:3871`), поэтому линия возвращается после смены стиля/языка.
- `fitDayMap()` вписывает точки в экран (`fitBounds`, padding, maxZoom 16) и запускает `animateDayLine()` (`:3699-3727`): линия растёт по накопленному haversine-расстоянию, 0.5–1.6 с, `requestAnimationFrame`, отключается при `prefers-reduced-motion`.
- Отдельного слоя остановок/подсветки нет. Остановки — обычные маркеры каталога; клик по строке списка делает `flyTo` и открывает карточку/попат (`focusSite`, `:3114-3118`), но не меняет hash и не выделяет маркер на линии.
- Кластеры не затрагиваются: линия — отдельный слой; кластеризация `sites` продолжает работать.
- Одновременно отображается **только один** маршрут: `stage0.dayShared` — одно значение, source `amg-day` — один; открытие другого маршрута заменяет предыдущий.
- Отдельной геометрии маршрута нет: нет поля `geometry` в `routes.json`, нет routing API, нет GPX/трека; расстояния — haversine по прямой, время — `WALK_M_PER_MIN = 83.3` (≈5 км/ч), минимум 1 мин (`:2962-2970`).
- Внешняя навигация (`ROUTE_PROVIDERS`, `:1012-1018`; `routeButtons`, `:2001-2007`) — только **до одного места**:
  - Яндекс: `rtext=~lat,lng&rtt=pd` (пешеходный маршрут до точки);
  - Google: `destination=lat,lng&travelmode=walking`;
  - Apple: `daddr=lat,lng&dirflg=w`;
  - OSM: точка на карте.
  - Ссылки открываются в новой вкладке (`target="_blank" rel="noopener"`), но не строят маршрут по всем остановкам, не поддерживают waypoints и не используют API-ключи. В панели «Мой день» таких ссылок нет — только в карточках/попапах места/впечатления.
- `streetViewBtn` (`:1992-1999`) — Google Street View для одного места, не для маршрута.

**Потребует разработки**

- Слой/стиль остановок и подсветка выбранной остановки.
- Несколько одновременных маршрутов (отдельные source/id на маршрут).
- Реальная геометрия (GPX/LineString по дорогам/тропам), расстояние/время по треку, высоты/сложность.
- Маршрутная внешняя навигация с waypoints.
- Лимит 25 для готовых маршрутов и/или явное решение о другом лимите.

### 2.5 Интерфейс и локализация

- Каталог готовых маршрутов — не отдельный экран, а блок внутри панели «Мой день»: `renderDay()` выводит `stage0.routes` плоским списком кнопок `data-ready` с `title`, `theme`, числом точек и расстоянием (`index.html:3651-3654`); данные грузятся при открытии панели (`openDay`, `:3673-3676`; `loadRoutes`, `:3678-3683`).
- Панель маршрута — `#day` (role=dialog): заголовок, описание (`theme` + `desc`), список, итог, поле имени, готовые маршруты, help, кнопки (`renderDay`, `:3631-3669`; `routeHelpHtml`, `:3670-3672`). Мобильная версия — нижняя панель с `max-height:78%`, десктоп — левая панель 440 px (`:77-82`); на coarse pointer контролы 42 px (`:127`).
- `Overlays` (`:2255-2285`) управляет стеком панелей и блокировкой карты; `day` зарегистрирован вместе с `passport`/`report` (`:3839-3841`), открывается по `#btnDay` (`:3844`).
- Фильтров/поиска/категорий у маршрутов нет. `theme` — локализованная строка, не ключ; категории каталога (`CATEGORIES`, `siteCat`) к маршрутам не применяются.
- Локализация:
  - тексты UI — `LB` (`:805-840`), выбор `pick()`/`LANG_ORDER` (`:693-701`);
  - данные маршрута — `{ru,en,ka}`, валидатор требует все три (`validate-routes.mjs:21`);
  - смена языка перерисовывает открытую панель (`:3865-3869`), `document.documentElement.lang` обновляется (`:2918`);
  - `<title>`, `meta description`, OG/Twitter — статичные, общие для сайта (`index.html:6-24`); при открытии маршрута не меняются;
  - `sitemap.xml` содержит только `/`, `privacy.html`, `license.html`; hash-ссылки маршрутов не индексируются отдельно;
  - `navigator.share` передаёт title маршрута в системный лист, но превью ссылки в мессенджерах берётся из статичных OG-мета страницы.
- Естественная точка встраивания отдельного каталога: существующий overlay `#day` и связка `loadRoutes`/`renderDay` (там уже есть список готовых маршрутов), либо новый overlay, зарегистрированный через `Overlays.register` рядом с `passport`/`day`/`report`; карта и текущая навигация при этом не затрагиваются. Это констатация точки расширения, не предложение реализации.

### 2.6 GitHub Pages и публикация

- Загрузка `routes.json`: `loadRoutes()` → `getJson('data/routes.json')` (`index.html:3679`), по требованию (при открытии панели или `#ready=`), промис кэшируется в `stage0.routesP`; повторное открытие панели в той же сессии файл не перезапрашивает.
- Кэш: service worker отдаёт `*.json`/`*.geojson` network-first с fallback в кэш (`sw.js:14-22`), поэтому онлайн-правки маршрутов видны без смены версии SW; офлайн — последняя кэшированная копия.
- CI: `pages.yml` запускается на `workflow_dispatch` и `push` в `main` (`:2-5`); шаг валидации (`:27-31`) включает `node scripts/validate-routes.mjs`; `cp -r data site/` (`:105`) публикует `routes.json` как есть. Отдельного шага сборки/сплита маршрутов нет.
- Проверка до публикации: локально `node scripts/validate-routes.mjs` (`README.txt:29`, `docs/RUNBOOK.md:25`) или полный набор валидаторов. CI проверит только после push в `main`; PR не запускает `pages.yml`, отдельного preview нет. При ошибке валидации job падает до деплоя, сайт остаётся на предыдущей успешной публикации.
- Ограничения GitHub Pages, существенные для маршрутов: опубликованный сайт ≤1 ГБ, деплой ≤10 минут, мягкий лимит трафика 100 ГБ/мес, мягкий лимит 10 сборок/час (для сборки через custom Actions не применяется). `routes.json` — 5 320 байт; на фоне 11 PMTiles-пакетов маршруты не являются ограничением. Архитектура статическая: весь `routes.json` скачивается клиентом целиком, без серверной фильтрации/пагинации; при росте каталога это остаётся одним JSON-файлом.
- Per-route страниц нет: маршруты живут в hash-фрагментах одной страницы; SEO/превью для отдельного маршрута текущая схема не даёт.

## 4. Переиспользуемые механизмы

- **Канонические ID и place-centric модель**: `site-NNNN` + `topic`/`poi_kind`/`description`/`media` уже позволяют держать на карте места без арт-работ; 41 такое место существует и отображается (`index.html:1160-1161`, `1184-1196`).
- **Ссылочная модель маршрута**: `stops` из ID — без дублирования названий/координат; один объект можно переиспользовать в нескольких маршрутах.
- **Валидация как шаблон**: `validate-routes.mjs` уже проверяет ID, i18n, дубли, существование, расстояния; новые поля можно валидировать в том же стиле.
- **Панель и линия**: `renderDay`/`dayGeo`/`drawDay`/`fitDayMap`/`animateDayLine` — готовый UI и рисование; для тематического каталога можно переиспользовать список, итог, вписывание и анимацию.
- **Шаринг/импорт**: `#ready=`, `#route=`, `dayShareUrl`, `openSharedRoute`, `saveSharedRoute`, `copyDayList` — полностью клиентские, без сервера.
- **Локализация**: `pick()` + `{ru,en,ka}` в данных; перерисовка панели при смене языка.
- **Overlays/CSS**: `Overlays.register/show/hide` и стили `#day` дают мобильную нижнюю панель и десктопную боковую без изменения карты.
- **Карта и кластеры**: линия — отдельный source/слой, не мешает кластерам; `style.load` восстанавливает слой.
- **Кэш и публикация**: network-first для JSON + `cp -r data` + CI-валидатор — минимальная инфраструктура уже есть.
- **Фото**: `media[]` и `mediaHtml` существуют для карточек; в маршруте не используются, но данные доступны для части мест.

## 5. Ограничения и риски

Подтверждено кодом/данными:

1. **Готовые маршруты ограничены art-active местами**: `validate-routes.mjs:27`; 41 place-centric место без работ и 343 места без активной работы не могут попасть в готовый маршрут, хотя часть из них — бани, монастыри, наследие — типичный тематический контент.
2. **«Впечатления» не адресуемы**: в `experiences.geojson` нет стабильного `id`; маршруты читают только `sites.geojson`.
3. **Нет тематических полей**: только `theme` свободным текстом; нет тегов/категории/длительности/транспорта/сезона/сложности/источников/заметок к остановкам.
4. **Нет геометрии**: только прямые отрезки; расстояния — haversine, время — 5 км/ч; для хайкинга/архитектурных прогулок этого недостаточно.
5. **Один маршрут на карте**: один source `amg-day`; несколько маршрутов одновременно не отображаются.
6. **Нет подсветки остановок**: только линия; `focusSite` не выделяет маркер и не пишет hash.
7. **Лимит 25 непоследователен**: личный день и `#route=` ограничены, `openReadyRoute` — нет (`:3692`); текущие готовые 8–17, но будущий маршрут может превысить.
8. **Stale ID в личном дне**: `renderDay()`/`copyDayList()` не фильтруют отсутствующие в каталоге ID; после удаления места возможна ошибка панели (`index.html:3636-3647`, `3743`). `dayGeo()`/`fitDayMap()` при этом фильтруют.
9. **Сохранение готового маршрута перезаписывает личный день** без подтверждения (`saveSharedRoute`, `:3769`).
10. **Скрытый конфликт личного и чужого маршрута**: пока открыт `dayShared`, добавления в личный день не видны; счётчик кнопки считает личный день.
11. **Хрупкий клиентский разбор**: битый маршрут в `routes.json` скрывает весь список готовых; битый `%` в `#route=` может бросить исключение; неизвестный `#ready=` молчит.
12. **Нет PR-валидации/превью**: `pages.yml` не реагирует на `pull_request`; проверка новых маршрутов — только локально или после push в `main`.
13. **Нет per-route SEO/метаданных**: hash-ссылки, статичные `<title>`/OG, `sitemap.xml` без маршрутов; превью в мессенджерах общее для сайта.
14. **Нет фото и источников маршрута**: маршрут не выводит `media[]` и не хранит `sources`; фото есть у 45 мест, но не в маршрутном UI.
15. **Контент сейчас узкий**: 4 маршрута, все Тбилиси, 51 остановка, 1 остановка с медиа; 230 из 573 мест проходят текущий статусный фильтр.
16. **Валидатор статуса смотрит только первую работу сайта** (`validate-routes.mjs:12`); сейчас у 3 сайтов несколько работ и ни у одного нет смешанных статусов, но при будущих данных это может расходиться с агрегированным `siteStatus` (`index.html:1020-1023`).
17. **GitHub Pages**: опубликованный сайт ≤1 ГБ, деплой ≤10 мин, 100 ГБ/мес мягкого трафика; для `routes.json` (5,3 КБ) это не ограничение, но схема — один статический JSON без серверной фильтрации и без per-route страниц.
