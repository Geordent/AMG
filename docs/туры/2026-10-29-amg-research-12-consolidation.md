### 1.2. Схема записи

Реестр — JSONL, одна строка = один кандидат. Поля:

| Поле | Содержание |
|---|---|
| `candidate_id` | `AMGxx-NNN`, исходный исследовательский ID; уникален и не переиспользуется |
| `source_candidate_id`, `source_batch`, `source_file` | Происхождение записи |

| `entity_type`, `entity_types` | `site`, `route`, `event`, `experience`, `complex`, `tradition` |

| `description` | Краткий оригинальный исследовательский текст; не финальная публикационная карточка |
| `visitor_info` | `access`, `seasonality`, `hours`, `fee`; только то, что указано в источнике |
| `route_fit` | Пригодность как остановки/маршрута; без выдуманной длительности |
| `amg_links` | `sites`, `experiences`, `match_status` |
| `identity` | `aliases`, `same_place_as` (пары дубликатов), `complex_members` |
| `verification` | `research_status`, `source_class`, `url_status`, `source_urls`, `source_labels`, `missing` |
| `decision` | `code`, `label_ru`, `score`, `reason`, `decided_at` |
| `claims` | Проверяемые утверждения; URL-проверка и ссылки на источники |
| `audit` | Даты, пакет, файл, версия реестра |

## 6. Рекомендации по подготовке данных для AMG

1. **Стабильные ID.** Оставить `AMGxx-NNN` как immutable `source_candidate_id` в исследовательском реестре. При принятии кандидата присваивать AMG `site-NNNN`/`experience` ID и хранить связь в `amg_links`, а не переписывать исходный ID. Для концептуальных мест использовать `canonical_place_key` (например, `georgia:nature:truso-travertines`) и `same_place_as` для пар.
2. **Слой исследований отдельно.** `registry.jsonl`, `source-catalog.json`, `decisions.jsonl` — в `research/`, не в `data/`. Не публиковать кандидатов автоматически; публикация — только после решения редактора и прохождения валидаторов.
3. **Совместимость с `sites.geojson`.** Принятый SITE должен получить `site-NNNN`, `city`, `name{ru,en,ka}`, `address`, `precision`, `access`, `sources`, `geometry`; для place-centric — `topic`/`poi_kind`; фото — `media[]` по действующим правилам. Только после `validate-data`.
4. **Совместимость с `experiences.geojson`.** Принять fingerprints из `2026-10-29-amg-research-12-experience-identities.jsonl` как временную идентичность; добавить стабильный `uid`/`id` в слой, не использовать номер строки. Коммерческие впечатления (винодельни, мастер-классы) хранить как `experience`/`site` с явным `access`.
5. **Маршруты.** Не втискивать ROUTE-кандидатов в `routes.json.stops`: текущая схема не хранит геометрию/GPX/длительность. Нужна отдельная модель маршрута с геометрией, остановками, сложностью и сезоном; `routes.json` — только готовые городские маршруты после проверки.
6. **География.** Добавить справочник регионов и муниципалитетов (ka/en/ru + коды/границы), а `cities.json` оставить справочником населённых пунктов. Координаты брать из NSDI/официальных источников, а не из текстовых описаний.
7. **Источники и утверждения.** Ввести `source-catalog.json` с `source_id`, URL, владельцем, типом, авторитетом, условиями переиспользования и `last_checked`; каждое существенное утверждение — отдельный claim с `epistemic_status` (`confirmed`/`inferred`/`hypothesis`/`unknown`).
8. **Редакционные решения.** Хранить `decisions.jsonl` с `CONSIDER`/`VERIFY`/`DEFER`/`REJECT`/`ALREADY_IN_AMG`, причиной и датой. `CONSIDER` не равно публикации; для карты обязательны координаты, доступ и источник.
9. **Приоритет проверки.** Сначала 8 пар-дубликатов и 5 POSSIBLE, затем 30 CONSIDER (геокодирование + источники + доступ), затем 134 VERIFY по темам с наибольшим разрывом: наследие (03), хайкинг (05), гастрономия (07), бани (08), искусство (10), смешанный (11).
10. **Сохранение отрицательных результатов.** Не удалять отклонённые/отложенные записи; хранить причину, дату и источник. Не превращать отсутствие найденных сведений в «объекта нет».
